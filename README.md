# Практическая работа: локальный DNS-сервер на Ubuntu Desktop

В этой работе вы создадите две виртуальные машины с Ubuntu Desktop в VMware Workstation и настроите собственный DNS-сервер.

Первая Ubuntu будет DNS-сервером с BIND9. Вторая Ubuntu будет DNS-клиентом.

В конце работы клиент должен уметь:

~~~text
dns.pgk.test    → IP DNS-сервера
client.pgk.test → IP DNS-клиента
~~~

При этом обычные интернет-домены тоже должны продолжить работать:

~~~text
yandex.ru
ubuntu.com
github.com
~~~

Работа рассчитана на Ubuntu Desktop 24.04 LTS. Если преподаватель выдал другой близкий образ Ubuntu Desktop, названия отдельных кнопок могут немного отличаться, но порядок действий остаётся тем же.

> В примерах ниже используются адреса 192.168.100.128 и 192.168.100.129. У вас VMware почти наверняка выдаст другие адреса. Не копируйте примерные IP вслепую: сначала выполните шаг 5 и запишите свои значения.

## Что мы создаём

Для работы нужны две виртуальные машины. У каждой будет только один сетевой адаптер в режиме NAT.

~~~text
                         Интернет
                            │
                            │
                     VMware NAT
                            │
              ┌─────────────┴─────────────┐
              │                           │
              ▼                           ▼
┌────────────────────────┐   ┌────────────────────────┐
│ Ubuntu Desktop №1      │   │ Ubuntu Desktop №2      │
│                        │   │                        │
│ dns-server             │   │ dns-client             │
│ BIND9                  │   │ использует наш DNS     │
│ dns.pgk.test           │   │ client.pgk.test        │
└────────────────────────┘   └────────────────────────┘
~~~

Обе виртуальные машины находятся в одной NAT-сети VMware. Поэтому они:

- получают доступ в интернет;
- получают IP-адреса от DHCP VMware;
- могут обращаться друг к другу по IP-адресам.

Для этой работы:

- не нужен второй сетевой адаптер;
- не нужен Host-only;
- не нужно открывать Virtual Network Editor;
- не нужен пароль администратора Windows.

Все команды с sudo выполняются внутри Ubuntu. Для них используется пароль пользователя Ubuntu, который вы создадите при установке.

## Что такое DNS

DNS — система доменных имён.

Её задача — преобразовать имя в IP-адрес.

Например:

~~~text
dns.pgk.test
        ↓
       DNS
        ↓
192.168.100.128
~~~

Когда пользователь вводит имя, клиент сначала узнаёт IP-адрес через DNS, а уже после этого подключается к нужному компьютеру.

В этой работе BIND9 будет выполнять две задачи.

Для локальной зоны:

~~~text
pgk.test
~~~

он будет отвечать сам.

Для обычных интернет-доменов:

~~~text
yandex.ru
ubuntu.com
github.com
~~~

он будет получать ответ через внешние DNS-серверы.

### Какие записи мы используем

| Тип | Назначение | Пример |
| --- | --- | --- |
| A | Имя → IPv4-адрес | dns.pgk.test → IP сервера |
| NS | DNS-сервер зоны | pgk.test обслуживает dns.pgk.test |
| SOA | Основная информация о зоне | служебная запись зоны |

### Почему pgk.test, а не pgk.local

Для лабораторной работы используется зона:

~~~text
pgk.test
~~~

Зона .test предназначена для тестов и примеров.

Зону .local лучше не использовать: в Linux она часто связана с mDNS, поэтому запросы могут обрабатываться не обычным DNS.

## Что нужно запомнить перед началом

С шага 5 и до конца работы обе виртуальные машины должны быть запущены одновременно.

После шага 5 вы запишете два значения:

~~~text
IP DNS-сервера
IP DNS-клиента
~~~

В примерах будет использоваться:

~~~text
DNS-сервер: 192.168.100.128
DNS-клиент: 192.168.100.129
~~~

У вас адреса будут другими.

Если в инструкции написано:

~~~text
192.168.100.128
~~~

подставляйте IP своего DNS-сервера.

Если написано:

~~~text
192.168.100.129
~~~

подставляйте IP своего DNS-клиента.

После того как вы записали адреса, не перезагружайте виртуальные машины без необходимости до окончания работы. DHCP VMware может выдать другой IP.

## Шаг 1. Проверьте режим NAT

**Где выполняем:** VMware Workstation.

Обе виртуальные машины должны использовать обычный сетевой адаптер VMware в режиме NAT.

Никакие дополнительные виртуальные сети создавать не нужно.

При создании виртуальной машины в разделе Network Adapter должен быть выбран:

~~~text
NAT
~~~

Обычно VMware устанавливает этот режим автоматически.

> Не открывайте Virtual Network Editor и не добавляйте второй сетевой адаптер. Для этой работы это не требуется.

## Шаг 2. Создайте виртуальную машину DNS-сервера

**Где выполняем:** VMware Workstation.

1. Откройте VMware Workstation.
2. Выберите **File → New Virtual Machine**.
3. Выберите **Typical (recommended)**.
4. Нажмите **Next**.
5. Выберите **I will install the operating system later**.
6. Нажмите **Next**.
7. Выберите **Linux**.
8. В версии выберите **Ubuntu 64-bit**.
9. Нажмите **Next**.
10. Имя виртуальной машины укажите:

~~~text
Ubuntu DNS Server
~~~

11. Выберите папку для виртуальной машины.
12. Нажмите **Next**.
13. Размер виртуального диска укажите не менее 20 ГБ.
14. Нажмите **Next**.
15. Нажмите **Customize Hardware**.
16. Для памяти укажите не менее 2048 МБ. Если компьютер позволяет, лучше 4096 МБ.
17. Для процессора достаточно 2 ядер.
18. Откройте **CD/DVD**.
19. Выберите **Use ISO image file**.
20. Укажите ISO-образ Ubuntu Desktop.
21. Откройте **Network Adapter**.
22. Убедитесь, что выбран режим **NAT**.
23. Нажмите **Close**.
24. Нажмите **Finish**.

Виртуальная машина создана.

## Шаг 3. Установите Ubuntu на DNS-сервер

**Где выполняем:** виртуальная машина Ubuntu DNS Server.

Запустите виртуальную машину.

В установщике Ubuntu:

1. Выберите язык.
2. Выберите раскладку клавиатуры.
3. Выберите установку Ubuntu.
4. Если установщик предлагает обычную или интерактивную установку, оставьте стандартный вариант.
5. Сетевые настройки оставьте автоматическими.
6. Для диска выберите установку на весь виртуальный диск.

Это безопасно: речь идёт только о виртуальном диске этой виртуальной машины.

Создайте пользователя и пароль. Имя пользователя может быть любым.

В качестве **имени компьютера** укажите:

~~~text
dns-server
~~~

Запомните пароль. Он понадобится для команд sudo.

При вводе пароля в терминале символы не отображаются даже точками или звёздочками. Это нормально: введите пароль и нажмите Enter.

Дождитесь завершения установки и выберите перезагрузку.

### Обязательно отключите установочный ISO

Во время перезагрузки Ubuntu может попросить удалить установочный носитель.

Если появляется сообщение вроде:

~~~text
Please remove the installation medium, then press ENTER
~~~

в VMware откройте:

**VM → Removable Devices → CD/DVD → Disconnect**

После этого нажмите Enter.

Когда установленная Ubuntu успешно загрузилась, дополнительно проверьте настройку:

1. Выключите виртуальную машину через меню Ubuntu или командой:

~~~bash
sudo poweroff
~~~

2. В VMware откройте **VM → Settings → CD/DVD**.
3. Снимите **Connect at power on**.
4. Убедитесь, что сетевой адаптер остаётся в режиме NAT.
5. Запустите виртуальную машину снова.

Если всё сделано правильно, при следующем запуске откроется установленная Ubuntu, а не установщик.

Откройте терминал:

~~~text
Ctrl + Alt + T
~~~

Проверьте имя компьютера:

~~~bash
hostname
~~~

Ожидаемый результат:

~~~text
dns-server
~~~

После запуска клиента откройте терминал и проверьте:

Ожидаемый результат:

dns-client
~~~

## Шаг 5. Узнайте IP-адреса и проверьте сеть

**Где выполняем:** сначала dns-server, затем dns-client.

### На DNS-сервере

Выполните:

~~~bash
ip -br -4 address
~~~

Пример:

~~~text
lo       UNKNOWN  127.0.0.1/8
ens33    UP       192.168.100.128/24
~~~

Не используйте 127.0.0.1.

Нужен адрес сетевого интерфейса VMware. В примере:

~~~text
192.168.100.128
~~~

Запишите свой адрес:

~~~text
IP DNS-сервера: ______________________
~~~

### На DNS-клиенте

Выполните:

~~~bash
ip -br -4 address
~~~

Пример:

~~~text
lo       UNKNOWN  127.0.0.1/8
ens33    UP       192.168.100.129/24
~~~

Запишите свой адрес:

~~~text
IP DNS-клиента: ______________________
~~~

### Проверьте связь между виртуальными машинами

На dns-client выполните:

~~~bash
ping -c 4 192.168.100.128
~~~

Вместо 192.168.100.128 подставьте IP своего dns-server.

Должны приходить ответы.

Теперь на dns-server выполните:

~~~bash
ping -c 4 192.168.100.129
~~~

Вместо 192.168.100.129 подставьте IP своего dns-client.

Должны приходить ответы.

Если виртуальные машины не видят друг друга, не переходите дальше. Сначала откройте раздел **Частые ошибки → Клиент не видит сервер по IP**.

### Проверьте интернет

На обеих Ubuntu выполните:

~~~bash
getent hosts ubuntu.com
~~~

В ответе должны появиться IP-адрес и имя ubuntu.com.

Пример:

~~~text
2620:2d:4000:1::28 ubuntu.com
~~~

Конкретный адрес может отличаться.

Это означает, что обычный DNS и интернет сейчас работают.

## Шаг 6. Установите BIND9

**Где выполняем:** только dns-server.

На dns-client BIND9 устанавливать не нужно.

Обновите информацию о пакетах:

~~~bash
sudo apt update
~~~

Установите DNS-сервер и диагностические утилиты:

~~~bash
sudo apt install bind9 bind9-utils dnsutils -y
~~~

Запустите BIND9 и включите его автоматический запуск:

~~~bash
sudo systemctl enable --now bind9
~~~

Проверьте:

~~~bash
systemctl is-active bind9
~~~

Ожидаемый ответ:

~~~text
active
~~~

Проверьте порт 53:

~~~bash
sudo ss -lntup | grep :53
~~~

Вы должны увидеть процесс named или bind9, слушающий порт 53.

На Ubuntu Desktop также может отображаться systemd-resolved на адресе 127.0.0.53. Это нормально.

## Шаг 7. Настройте BIND9

**Где выполняем:** dns-server.

Откройте файл:

~~~bash
sudo nano /etc/bind/named.conf.options
~~~

Внутри файла найдите блок:

~~~text
options {
    ...
};
~~~

Замените содержимое файла следующим:

~~~text
options {
    directory "/var/cache/bind";

    recursion yes;

    allow-query {
        localhost;
        localnets;
    };

    allow-recursion {
        localhost;
        localnets;
    };

    forwarders {
        1.1.1.1;
        8.8.8.8;
    };

    dnssec-validation auto;

    listen-on-v6 {
        none;
    };
};
~~~

В этой конфигурации не нужно вручную писать IP или подсеть VMware.

Значение localnets означает сети, непосредственно подключённые к DNS-серверу.

Параметр forwarders указывает внешние DNS-серверы, которым BIND9 может передавать запросы к обычным интернет-доменам.

Если в вашей учебной сети прямые запросы к 1.1.1.1 и 8.8.8.8 запрещены, это будет видно на шаге 10. В разделе частых ошибок описано, как в таком случае использовать DNS, который VMware уже выдала Ubuntu.

### Как сохранить файл в nano

1. Нажмите **Ctrl + O**.
2. Нажмите **Enter**.
3. Нажмите **Ctrl + X**.

Пока BIND9 не перезапускайте. Сначала создадим локальную зону.

## Шаг 8. Создайте локальную DNS-зону

**Где выполняем:** dns-server.

Откройте:

~~~bash
sudo nano /etc/bind/named.conf.local
~~~

Добавьте в конец файла:

~~~text
zone "pgk.test" {
    type master;
    file "/etc/bind/db.pgk.test";
};
~~~

Сохраните файл:

~~~text
Ctrl + O
Enter
Ctrl + X
~~~

Теперь BIND9 знает, что зона pgk.test должна храниться в файле:

~~~text
/etc/bind/db.pgk.test
~~~

Сам файл создадим следующим шагом.

## Шаг 9. Создайте DNS-записи

**Где выполняем:** dns-server.

Перед продолжением ещё раз посмотрите записанные на шаге 5 значения.

Пример:

~~~text
IP DNS-сервера: 192.168.100.128
IP DNS-клиента: 192.168.100.129
~~~

В следующем файле обязательно замените эти два адреса своими.

Создайте файл:

~~~bash
sudo nano /etc/bind/db.pgk.test
~~~

Добавьте:

~~~text
$TTL 86400

@   IN  SOA dns.pgk.test. admin.pgk.test. (
        1
        3600
        1800
        604800
        86400
)

@       IN  NS      dns.pgk.test.

dns     IN  A       192.168.100.128
server  IN  A       192.168.100.128
client  IN  A       192.168.100.129
~~~

Замените:

- 192.168.100.128 на IP своего dns-server;
- 192.168.100.129 на IP своего dns-client.

Сохраните файл.

В результате должны появиться три имени:

~~~text
dns.pgk.test    → IP dns-server
server.pgk.test → IP dns-server
client.pgk.test → IP dns-client
~~~

### Что означает число 1

Это Serial — версия DNS-зоны.

Если позже вы меняете записи в файле зоны, увеличьте число:

~~~text
1 → 2 → 3
~~~

### Почему после dns.pgk.test стоит точка

Полное имя в файле зоны заканчивается точкой:

~~~text
dns.pgk.test.
~~~

Она показывает BIND9, что это полное доменное имя и к нему не нужно дописывать имя текущей зоны.

## Шаг 10. Проверьте и запустите DNS-сервер

**Где выполняем:** dns-server.

Сначала проверьте общую конфигурацию:

~~~bash
sudo named-checkconf
~~~

Если команда ничего не вывела — это хороший результат: синтаксических ошибок нет.

Теперь проверьте файл зоны:

~~~bash
sudo named-checkzone pgk.test /etc/bind/db.pgk.test
~~~

Ожидаемый результат:

~~~text
zone pgk.test/IN: loaded serial 1
OK
~~~

Если вместо OK показана ошибка, не переходите дальше. Исправьте указанную строку в файле зоны и выполните проверку снова.

После успешной проверки перезапустите BIND9:

~~~bash
sudo systemctl restart bind9
~~~

Проверьте:

~~~bash
systemctl is-active bind9
~~~

Ожидаемый результат:

~~~text
active
~~~

Теперь проверьте, что сервер отвечает сам себе.

Подставьте IP своего dns-server:

~~~bash
dig @192.168.100.128 dns.pgk.test +short
~~~

Ожидаемый ответ — IP dns-server.

Например:

~~~text
192.168.100.128
~~~

Проверьте внешний домен через BIND9:

~~~bash
dig @192.168.100.128 yandex.ru +short
~~~

Должен появиться один или несколько IP-адресов.

Если локальное имя работает, а yandex.ru нет, откройте раздел **Частые ошибки → Локальные имена работают, а интернет-домены нет**.

## Шаг 11. Проверьте UFW

**Где выполняем:** dns-server.

Проверьте состояние межсетевого экрана:

~~~bash
sudo ufw status
~~~

### Если написано inactive

Ничего включать не нужно.

Для этой практической просто переходите к следующему шагу.

### Если написано active

Разрешите DNS-запросы от клиента.

Вместо 192.168.100.129 подставьте IP своего dns-client:

~~~bash
sudo ufw allow from 192.168.100.129 to any port 53 proto udp
sudo ufw allow from 192.168.100.129 to any port 53 proto tcp
~~~

Проверьте:

~~~bash
sudo ufw status
~~~

Теперь клиенту разрешено обращаться к DNS-серверу по UDP и TCP на порт 53.

## Шаг 12. Проверьте DNS напрямую с клиента

**Где выполняем:** dns-client.

Установите диагностические утилиты:

~~~bash
sudo apt update
sudo apt install dnsutils -y
~~~

Пока системные настройки DNS клиента не меняйте.

Сначала напрямую обратитесь к BIND9.

Вместо 192.168.100.128 используйте IP своего dns-server.

Проверьте сервер:

~~~bash
dig @192.168.100.128 dns.pgk.test +short
~~~

Ожидаемый ответ:

~~~text
192.168.100.128
~~~

Проверьте запись клиента:

~~~bash
dig @192.168.100.128 client.pgk.test +short
~~~

Ожидаемый ответ:

~~~text
192.168.100.129
~~~

Проверьте обычный интернет-домен:

~~~bash
dig @192.168.100.128 yandex.ru +short
~~~

Должен появиться один или несколько IP-адресов.

Дополнительно проверьте:

~~~bash
nslookup dns.pgk.test 192.168.100.128
~~~

Если все три проверки работают, DNS-сервер полностью готов.

Только после этого меняйте системный DNS клиента.

## Шаг 13. Укажите свой DNS на клиенте

**Где выполняем:** dns-client.

Откройте в Ubuntu:

**Settings → Network**

Найдите проводное подключение **Wired** и откройте его настройки кнопкой с шестерёнкой.

Откройте вкладку **IPv4**.

Адрес должен остаться в режиме:

~~~text
Automatic (DHCP)
~~~

Не переводите IP-адрес в Manual.

В разделе DNS:

1. Отключите **Automatic** рядом с DNS.
2. Укажите только IP своего dns-server.

Например:

~~~text
192.168.100.128
~~~

3. Не добавляйте вторым DNS 1.1.1.1 или 8.8.8.8. Клиент должен отправлять DNS-запросы нашему BIND9.
4. Нажмите **Apply**.

Не перезагружайте виртуальную машину.

Если настройки не применились сразу, в **Settings → Network** выключите Wired и включите его снова.

Очистите локальный DNS-кэш:

~~~bash
sudo resolvectl flush-caches
~~~

Проверьте:

~~~bash
resolvectl status
~~~

Найдите активное проводное подключение.

В нём должен быть указан IP вашего DNS-сервера.

Например:

~~~text
Current DNS Server: 192.168.100.128
DNS Servers: 192.168.100.128
~~~

Ubuntu Desktop использует локальную службу systemd-resolved. Поэтому в некоторых программах вы можете увидеть адрес:

~~~text
127.0.0.53
~~~

Это нормально. 127.0.0.53 — локальный DNS-посредник Ubuntu, который уже отправляет запрос нашему BIND9.

## Шаг 14. Выполните итоговую проверку

**Где выполняем:** dns-client.

Теперь адрес DNS-сервера вручную в командах больше не указываем.

### Проверка локального имени сервера

~~~bash
dig dns.pgk.test +short
~~~

Должен вернуться IP dns-server.

### Проверка локального имени клиента

~~~bash
dig client.pgk.test +short
~~~

Должен вернуться IP dns-client.

### Проверка через системный resolver Ubuntu

~~~bash
resolvectl query server.pgk.test
~~~

В ответе должен быть IP dns-server.

### Проверка через ping

~~~bash
ping -c 4 dns.pgk.test
~~~

В первой строке вы должны увидеть IP dns-server.

### Проверка обычного интернет-домена

~~~bash
dig yandex.ru +short
~~~

Должны появиться IP-адреса Яндекса.

Проверьте ещё:

~~~bash
dig ubuntu.com +short
dig github.com +short
~~~

Локальные и интернет-домены должны работать одновременно.

В результате схема выглядит так:

~~~text
dns-client
    │
    │ DNS-запрос
    ▼
dns-server / BIND9
    │
    ├── pgk.test → отвечает сам
    │
    └── yandex.ru → получает ответ через внешний DNS
~~~

## Что показать преподавателю

Работа готова, если студент может показать следующие проверки.

### На dns-server

~~~bash
hostname
ip -br -4 address
systemctl is-active bind9
sudo named-checkconf
sudo named-checkzone pgk.test /etc/bind/db.pgk.test
sudo ss -lntup | grep :53
~~~

Ожидается:

- hostname равен dns-server;
- BIND9 имеет состояние active;
- named-checkconf не показывает ошибок;
- named-checkzone заканчивается OK;
- порт 53 слушается DNS-сервером.

### На dns-client

~~~bash
hostname
ip -br -4 address
resolvectl status
dig dns.pgk.test +short
dig client.pgk.test +short
dig yandex.ru +short
~~~

Ожидается:

- hostname равен dns-client;
- в resolvectl status указан IP dns-server;
- dns.pgk.test возвращает IP сервера;
- client.pgk.test возвращает IP клиента;
- yandex.ru возвращает один или несколько публичных IP.

## Частые ошибки

### После перезапуска снова открывается установщик Ubuntu

Причина: ISO всё ещё подключён как виртуальный CD/DVD.

Выключите виртуальную машину.

Откройте:

**VM → Settings → CD/DVD**

Снимите:

~~~text
Connect at power on
~~~

Запустите виртуальную машину снова.

### Клиент не видит сервер по IP

На обеих машинах выполните:

~~~bash
ip -br -4 address
~~~

Проверьте:

1. Обе машины запущены.
2. У обеих один Network Adapter.
3. У обеих выбран NAT.
4. Вы используете текущие IP-адреса.
5. Адрес 127.0.0.1 не используется для связи между машинами.

Проверьте с клиента:

~~~bash
ping -c 4 192.168.100.128
~~~

Перед командой замените 192.168.100.128 на текущий IP своего dns-server.

Если связи по IP нет, DNS настраивать ещё рано.

### Я скопировал 192.168.100.128, но ничего не работает

192.168.100.128 — только пример из инструкции.

Выполните на dns-server:

~~~bash
ip -br -4 address
~~~

и используйте реальный IP вашей машины.

То же самое относится к 192.168.100.129.

### BIND9 не запускается

Выполните:

~~~bash
sudo named-checkconf
~~~

Затем:

~~~bash
sudo named-checkzone pgk.test /etc/bind/db.pgk.test
~~~

Если есть ошибка, команда обычно показывает файл и проблемную строку.

Посмотрите журнал:

~~~bash
sudo journalctl -u bind9 --no-pager -n 50
~~~

После исправления:

~~~bash
sudo systemctl restart bind9
systemctl is-active bind9
~~~

### В ss виден 127.0.0.53:53

Ubuntu Desktop использует systemd-resolved.

Адрес:

~~~text
127.0.0.53
~~~

не является IP вашего BIND9-сервера и не является ошибкой.

BIND9 должен также слушать реальный IP сетевого интерфейса Ubuntu.

Проверьте:

~~~bash
sudo ss -lntup | grep :53
~~~

### dig напрямую работает, а обычный dig без @IP не работает

Например, работает:

~~~bash
dig @192.168.100.128 dns.pgk.test +short
~~~

но не работает:

~~~bash
dig dns.pgk.test +short
~~~

Это означает, что сам BIND9 работает, но dns-client ещё не использует его как системный DNS.

Проверьте:

~~~bash
resolvectl status
~~~

В активном Wired-подключении должен быть IP вашего dns-server.

Также проверьте, что в Settings → Network → Wired → IPv4 автоматический DNS отключён и вручную указан IP dns-server.

### Локальные имена работают, а интернет-домены нет

На dns-server проверьте:

~~~bash
getent hosts ubuntu.com
~~~

Если даже эта команда ничего не возвращает, сначала восстановите обычный интернет на dns-server.

Затем проверьте внешний DNS:

~~~bash
dig @1.1.1.1 yandex.ru +short
~~~

Если запрос работает, проверьте файл:

~~~bash
sudo nano /etc/bind/named.conf.options
~~~

Если запрос к 1.1.1.1 заканчивается timeout, узнайте DNS, который уже использует сам dns-server:

~~~bash
resolvectl status
~~~

Найдите у активного Wired-подключения строку **Current DNS Server**. Например:

~~~text
Current DNS Server: 192.168.100.2
~~~

В таком случае вместо публичных 1.1.1.1 и 8.8.8.8 можно указать этот адрес в блоке forwarders.

После этого сохраните файл, выполните named-checkconf и перезапустите BIND9.

Затем снова проверьте:

~~~bash
dig @192.168.100.128 yandex.ru +short
~~~

Не забудьте заменить 192.168.100.128 на IP своего dns-server.

Если прямой запрос к 1.1.1.1 работает, проверьте файл:

В нём должны быть:

~~~text
forwarders {
    1.1.1.1;
    8.8.8.8;
};
~~~

Проверьте конфигурацию и перезапустите BIND9:

~~~bash
sudo named-checkconf
sudo systemctl restart bind9
~~~

### yandex.ru работает, а pgk.test нет

Сначала проверьте BIND9 напрямую:

~~~bash
dig @192.168.100.128 dns.pgk.test +short
~~~

Перед командой замените 192.168.100.128 на IP своего dns-server.

Если прямой запрос работает, проблема находится в системной настройке DNS клиента.

Если прямой запрос не работает, проверьте:

~~~bash
sudo named-checkzone pgk.test /etc/bind/db.pgk.test
~~~

на dns-server.

### После изменения DNS-записи возвращается старый адрес

Откройте:

~~~bash
sudo nano /etc/bind/db.pgk.test
~~~

Увеличьте Serial.

Например:

~~~text
1 → 2
~~~

Затем:

~~~bash
sudo named-checkzone pgk.test /etc/bind/db.pgk.test
sudo systemctl restart bind9
~~~

На клиенте:

~~~bash
sudo resolvectl flush-caches
~~~

### После перезапуска IP-адрес изменился

DHCP VMware может выдать новый адрес.

Снова выполните на обеих машинах:

~~~bash
ip -br -4 address
~~~

Если изменился IP dns-server:

1. Исправьте A-записи dns и server в файле /etc/bind/db.pgk.test.
2. Увеличьте Serial.
3. Проверьте зону.
4. Перезапустите BIND9.
5. На dns-client укажите новый IP сервера в Settings → Network → Wired → IPv4 → DNS.

Команды на сервере:

~~~bash
sudo named-checkzone pgk.test /etc/bind/db.pgk.test
sudo systemctl restart bind9
~~~

Если изменился IP dns-client, исправьте запись client в файле зоны и снова увеличьте Serial.

### Запрос к DNS заканчивается timeout

С клиента сначала проверьте:

~~~bash
ping -c 4 IP_СЕРВЕРА
~~~

Если ping работает, проверьте на сервере:

~~~bash
systemctl is-active bind9
sudo ss -lntup | grep :53
sudo ufw status
~~~

Если UFW активен, убедитесь, что клиенту разрешён порт 53 по UDP и TCP.

## Что нужно понимать после выполнения

- DNS преобразует доменные имена в IP-адреса.
- DNS использует порт 53 по UDP и TCP.
- A-запись связывает имя с IPv4-адресом.
- NS-запись указывает DNS-сервер зоны.
- SOA хранит служебную информацию о DNS-зоне.
- BIND9 может быть авторитетным DNS-сервером для локальной зоны.
- BIND9 может передавать запросы к внешним DNS-серверам.
- Локальный DNS позволяет использовать удобные имена внутри организации или домашней сети.
- Собственный DNS не мешает работе обычных интернет-доменов, если внешние запросы настроены правильно.
- Если прямой запрос к BIND9 с явным указанием IP сервера работает, а обычное разрешение имени нет, нужно проверять DNS-настройки клиента.
- Если машины не видят друг друга по IP, сначала нужно исправить сеть, а уже потом DNS.
- Для учебных локальных зон удобно использовать .test.
- .local лучше не использовать для обычного DNS из-за mDNS.
